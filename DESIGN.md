# AppBlocks Web design contract

## Product and audience

AppBlocks Web is for developers and coding agents that need to produce complete, credible browser software while emitting substantially less source text. The showcase must prove the compiler rather than merely describe it.

## Surface jobs

- **Home — persuade:** establish the compact-language claim and show source beside rendered consequence.
- **Catalog — showcase/read:** make the block system inspectable by humans and models.
- **Guide — read:** make a first successful build possible without unstated knowledge.
- **Dashboard — operate:** prove that AppBlocks can generate application UI, stateful controls, data density and recovery states.

## Design thesis

Treat a compact AppBlocks file like an architectural score: restrained cobalt blueprint marks, warm drafting paper, sharp ink typography and measured grid annotations expand into a polished full interface. The first viewport must visibly connect concise source to substantial output.

## Direction and dials

- **Variance 7/10:** an asymmetric source-to-surface composition carries the idea without disrupting reading.
- **Motion 5/10:** compilation pulses, staggered reveals and spatial state changes explain cause and effect; reduced motion removes travel.
- **Density 6/10:** documentation and application surfaces are information-rich, while persuasion sections retain deliberate breathing room.

## Signature move

A vertical cobalt compilation rail travels through the home page. On wide screens it visually joins the compact source panel to progressively larger rendered blocks. On small screens it becomes a horizontal rule and ordered annotations.

## System

- **Paper:** warm near-white with faint blueprint grid; deep navy for dark surfaces.
- **Ink:** blue-black primary, slate secondary, muted drafting annotations.
- **Accent:** cobalt is reserved for compilation, actions, selection and focus.
- **Type:** system sans for interface and prose; system mono for AppBlocks, tokens and numerical data.
- **Geometry:** mostly square drafting geometry with small radii; larger curves only for floating interactive controls.
- **Motion:** 120/220/420ms durations, transform and opacity only, spring-like easing without animation dependencies.
- **Assets:** code-native SVG, CSS grid and typography. No stock imagery or fake social proof.

## Component voice

Controls are direct and technical without becoming sterile. Labels use concrete verbs. Data components prioritize alignment and scanability. Marketing blocks use editorial hierarchy rather than repeated card grids.

## Responsive and accessibility invariants

- No horizontal document overflow at 320 CSS pixels.
- Visible focus rings use the cobalt focus token and remain clear on every surface.
- Touch targets are at least 44px where controls are likely to be used on mobile.
- Navigation, dialogs, tabs, filters and forms work from the keyboard.
- Motion is disabled or reduced under `prefers-reduced-motion`.
- Content order remains meaningful without CSS or JavaScript.

## Avoid

- Purple gradient SaaS styling, glass panels and decorative glowing orbs.
- Centered hero followed by interchangeable three-card rows.
- Fake GitHub stars, customer logos, testimonials or performance measurements.
- Dead controls, ornamental animation or a terminal costume with no product function.
