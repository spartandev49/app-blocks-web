# Roadmap

Roadmap items are ordered by evidence required, not promised release date.

## Next verification frontier

- Rendered browser matrix at 320, 375, 768, 1440 and 1920 CSS pixels.
- Automated keyboard flow and accessibility-tree assertions using a pinned browser toolchain.
- Real tokenizer comparison across representative coding models, clearly separated by tokenizer.
- Larger benchmark corpus comparing AppBlocks source with equivalent hand-authored and model-authored frontend output.

## Language and block frontier

- Reusable named content/data declarations without losing source readability.
- Contract versioning and third-party block manifests.
- Explicit data-source and action adapters with permission declarations.
- Static sitemap, feed and structured-data blocks.
- Additional commerce, documentation and editor surface contracts.

## Renderer frontier

- Optional server-rendered framework target while preserving the canonical AST.
- Component-level export for projects that need conventional source ownership.
- Style-pack authoring format with contrast and state validation.

## Beyond web

- Extract a shared, versioned block-contract format only after the web engine demonstrates reliable model selection and measurable token reduction.
- Add separate domain engines for backend services, data workflows and automations instead of turning the web language into a universal grab bag.
- Preserve the same core guarantees across engines: compact intent, typed contracts, strict validation, deterministic expansion and explicit permission boundaries.

No item should be implemented solely because it broadens the feature list. It must demonstrate meaningful token reduction, reliable model selection and a tested user-facing outcome.
