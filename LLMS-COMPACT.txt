# AppBlocks Web compact contract

GOAL: emit the smallest valid .ab source that still contains real product content and behavior requirements. The compiler supplies tested layout, design, accessibility and browser interaction.

START
st "Project" r=r0000
  pg "/" title="Project"
    hr000
      ttl "Concrete promise" lvl=1
      txt "Specific useful explanation."
      b000 "Primary action" h="/start"

- Buttons: b000-b999. Headers: h000-h999. Footers: ft000-ft999.
- Heroes: hr000-hr999. Frames: fr000-fr999. Cards: cd000-cd999.
- Sections: sc000-sc999. Forms: fm000-fm999. Tables: tb000-tb999. Navigation: nv000-nv999.

RULES
1. Exactly two spaces per nesting level. No tabs.
2. Exactly one ttl/title with lvl=1 on each page.
3. Every fld/field needs l/label. Every image needs alt.
4. Use ln/link for destinations and bt/button for local actions.
5. Never output raw HTML, CSS, JavaScript or executable URL schemes.
6. Write real labels and content. Do not invent customers, metrics or integrations.
7. A recipe selects visual defaults; add product-specific structure and content.
8. Use the largest semantic block that matches the requested result.
9. Backend operations require real adapters, authorization and server validation.
10. Run: appblocks-v2 check file.ab --strict

QUERY ONLY WHAT IS NEEDED
appblocks-v2 recipe r7314
appblocks-v2 virtual b203
appblocks-v2 catalog carousel --json
appblocks-v2 normalize file.ab
