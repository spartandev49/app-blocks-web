DESIGN
- Choose exactly one site recipe: r=d0000 through r=d9999.
- Recipes coordinate palette, font pairing, visual system, shape, surface, motion, density and shadow.
- Use virtual IDs for differentiated blocks: hNNN hero, bNNN button, hdNNN header, ftNNN footer, frNNN frame, sNNN section, cNNN card, gNNN grid, fNNN feature, pNNN panel, nvNNN nav, fmNNN form, tbNNN table, dgNNN dialog, ctNNN CTA, prNNN pricing, tsNNN testimonials, chNNN chart, mtNNN metric, shNNN app shell. NNN is 000–999.
- Virtual IDs keep canonical semantics. Do not choose IDs by pretending they contain content; they select deterministic visual axes.

AUTHORING RULES
1. Use the largest semantic block that matches the requested outcome.
2. Put exactly one level=1 title on every page.
3. Give every field a visible label and every meaningful image useful alt text.
4. Use links for destinations and buttons for actions.
5. Shared header/footer belong under site. Use page layout=app for application shells.
6. Do not emit raw HTML, arbitrary JavaScript, javascript: URLs or data: URLs.
7. Do not fabricate customers, testimonials, metrics, certifications, integrations or backend success. Mark demonstration data.
8. Prefer a coherent recipe plus a few meaningful exceptions over random styling per block.
9. Retrieve only needed contracts: appblocks catalog <name-or-family> --json.
10. Validate strictly and repair every diagnostic: appblocks validate project.appblocks --strict --json.

WORKFLOW
Plan routes and each route’s job. Select one recipe. Retrieve relevant contracts. Write one coherent file. Strictly validate. Build. Inspect desktop and mobile. Change the AppBlocks source, not generated output.
