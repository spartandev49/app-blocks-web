# AppBlocks Web compact contract

GOAL: emit the smallest valid .ab source that still contains real product content and behavior requirements. The compiler supplies tested layout, design, accessibility, browser interaction and motion.

START
st "Project" r=r0000 fx=polished
  pg "/" title="Project"
    hr000
      ttl "Concrete promise" lvl=1
      txt "Specific useful explanation."
      b000 "Primary action" h="/start"

MOTION
Set one global profile on the site. It gives role-aware defaults to heroes, sections, collections, cards, buttons, navigation and application surfaces:

st "Project" r=r7314 fx=cinematic

Profiles: off quiet polished dynamic cinematic playful editorial application commerce dramatic

Use an exact deterministic recipe on one block:

cd203 fx=x731

Override only the needed axes:

b203 "Start" h="/start" hx=magnetic px=ripple
sc247 sx=parallax-y en=clip-up cx=cascade du=slow ix=strong
hr017 fx="hero sx:depth hx:spotlight"

Motion aliases:
- fx=profile, preset or x000-x999 recipe
- en=entrance, sx=scroll, hx=hover, px=press, lx=loop
- cx=child choreography, ez=easing, du=duration, dl=delay
- sg=stagger, og=origin, ix=intensity, rp=repeat

RULES
1. Exactly two spaces per nesting level. No tabs.
2. Exactly one ttl/title with lvl=1 on each page.
3. Every fld/field needs l/label. Every image needs alt.
4. Use ln/link for destinations and bt/button for local actions.
5. Never output raw HTML, CSS, JavaScript or executable URL schemes.
6. Write real labels and content. Do not invent customers, metrics or integrations.
7. A design recipe selects visual defaults; a motion profile selects coordinated behavior.
8. Use the largest semantic block that matches the requested result.
9. Backend operations require real adapters, authorization and server validation.
10. Run: appblocks-v2 check file.ab --strict
